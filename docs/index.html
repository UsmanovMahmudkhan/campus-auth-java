Java library and CLI for campus member account authentication.

Campus Auth Java wraps session-based login checks, HTML parsing, fallback authentication methods, and structured JSON output in a small Java 11 toolkit.

Get started View API reference 
java -jar target/campus-auth-java-0.3.4.jar student_id

Install

Build from source with Maven.

The project ships as a standard Maven package. Build once, then use the shaded jar from `target/` in local scripts, automation, or Java services.

Shell 
git clone https://github.com/UsmanovMahmudkhan/campus-auth-java.git
cd campus-auth-java
mvn clean package

Quickstart

Run the fallback authenticator.

Manual mode runs the configured authenticator sequence until it receives a definite authentication result. If a method cannot determine the result, the next method is tried.

1

Build

Create the runnable jar with Maven.

mvn clean package
2

Run

Pass an id and password, or omit the password for a prompt.

java -jar target/campus-auth-java-0.3.4.jar <id>
3

Read JSON

Use `success`, `is_auth`, `code`, and `body` to decide how to continue.

{"code":"success","is_auth":true}

CLI

Command line usage.

Automatic fallback

Runs the default sequence: `PortalSSOToken`, `ClassicSession`, `MoodlerSession`, `DosejongSession`.

java -jar target/campus-auth-java-0.3.4.jar <id> <password>

Specific authenticator

Choose one method when you know exactly which service flow you need.

java -jar target/campus-auth-java-0.3.4.jar <id> <password> PortalSSOToken

Ordered subset

Pass a comma-separated list to run only selected methods in order.

java -jar target/campus-auth-java-0.3.4.jar <id> <password> PortalSSOToken,DosejongSession

API reference

Call the toolkit from Java.

`AuthService` is the main entry point. Use `AuthResult` for fallback flows and `AuthResponse` for a single selected authenticator.

Java 
import campus.auth.java.AuthMethod;
import campus.auth.java.AuthResponse;
import campus.auth.java.AuthResult;
import campus.auth.java.AuthService;

AuthResult result = AuthService.authenticate("student_id", "password");

AuthResponse portal = AuthService.authenticate(
    "student_id",
    "password",
    AuthMethod.PORTAL_SSO_TOKEN
);

Responses

Structured output for every outcome.

Field Type Meaning
success boolean Whether the service returned a usable response.
is_auth boolean or null Definite authentication result, or null when unknown.
status_code integer or null HTTP status code, or null for timeouts.
code string Machine-readable result code.
body object Metadata, messages, or extracted member data.

Auth methods

Supported strategies.

PortalSSOToken

Checks portal SSO token behavior and maps known failure branches to stable response codes.

ClassicSession

Uses a session flow and extracts profile plus classic reading certification metadata.

MoodlerSession

Uses the LMS login flow and extracts name and major when the member panel is present.

DosejongSession

Uses a session login and extracts name plus major from the account information block.

Security

Handle credentials carefully.

  • Pass credentials at runtime. Do not commit secrets or `.env` files.
  • Prefer the interactive password prompt when running the CLI locally.
  • Check `is_auth` and `success` separately so server failures are not treated as credential failures.
  • Keep build output out of version control; `target/` is ignored.
